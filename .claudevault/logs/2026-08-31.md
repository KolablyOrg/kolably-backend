### Design points worth remembering
- Quota is enforced in `campaign_service._assert_campaign_quota_available`,
  called from the single campaign-creation entry point
  (`create_campaign_step1` — verified via grep that `insert_campaign` has
  exactly one call site, so there's no bypass path). 402, not 403 — an
  upgrade-shaped limit, not an access error.
- `resolve_plan()` reads `plan` + `subscription_status` +
  `current_period_end` together, never `plan` alone — a cancelled/expired
  row can't keep granting access just because the `plan` column wasn't
  separately reset. Unknown enum values degrade to `free`, never raise.
- `set_business_plan` is superadmin-only and `plan` is absent from
  `BusinessUpdateRequest` — verified by grep, not assumed from the
  docstring's claim.
- Phone number's PATCH-partial-update footgun: `CreatorUpdateRequest` is
  dumped with `exclude_none=True`, so `None` can't mean "clear this
  field." The validator emits `""` for a deliberate clear (distinct from
  omitting the key), and `creator_service` converts `""` to a real `NULL`
  at write time. Verified `phone` really is absent from
  `UpdateProfileRequest` (`PATCH /auth/me`'s allowlist) before trusting
  the code comment that claims it's dropped there silently.
