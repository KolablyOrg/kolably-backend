without registering that push sends the whole branch, not just the new
commit — `529dbb7` (the feature commit I'd just told the user I was
holding back) rode along underneath it and reached `origin/main` in the
same push. **A vault-log commit is not exempt from this** — any commit
on `main`, including a docs-only one, pushes everything beneath it.

Caught it immediately via `gh run list` (habit from earlier in this
session) rather than assuming the push was fine because the diff being

changes for the first time, in a real interpreter, independent of this

**Reusable lesson**: "I'll hold this commit and ask first" is not a
promise `git push` on the same branch can keep afterward — anything
already committed on `main` ships the instant *anything* on that branch
is pushed, regardless of what the pushed diff itself contains. Check
`git log <local>..origin/main` reachability before treating a "small"
push as low-risk, not just the diff of the commit being made.
